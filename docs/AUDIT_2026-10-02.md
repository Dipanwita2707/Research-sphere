# ResearchSphere — platform audit, 2 October 2026

Scope: backend (API, security, reliability), frontend, database, and feature completeness.
Fixed during this pass (not repeated below): `PublicationList` rewritten to spec (24 tests now pass, fake "Related articles"/"versions"/"Cited by #" controls removed); mock-backed `/research/analytics` now redirects to real DRD analytics; unused `ProfileSearch` and profile mocks deleted; profile photos added with a privacy toggle and a public photo endpoint; flaky IPR test timeout fixed (backend suite fully green); DRD overview cache scoped to user/tenant; globe's three.js now lazy-loaded.

Method: four independent read-only audits, each finding verified against the code; the two
worst backend findings were re-checked by hand. Branch `saas-hardening`, dev Neon database
(one tenant: SGT Demo University).

**Row-Level Security — remaining design work.** To move the app onto a role without BYPASSRLS, every
operation must carry its tenant to Postgres in the same round trip as the query (e.g. a batch
`$transaction([set_config(...), query])` from the Prisma extension, plus `SET LOCAL` at the start of
interactive transactions). Connection-level tagging is unsafe with Prisma 7's request batching
(verified: 2 of 6 concurrent foreign-tenant requests saw the other tenant's rows).

Status legend: **Critical** = exploitable now or blocks a core flow · **High** = serious, fix
before onboarding a second university · **Medium** · **Low**.

## 2. Backend

**Tests:** 36 suites, 614 passed / 2 skipped (DB suites need `RUN_DB_TESTS=1`). No tests for analytics, finance,
notifications, superadmin, uploads, core controllers, jobs, `protect`/`requirePermission`, permission & role management.

**Endpoint security scan** (`scripts/security/audit-endpoints.js`, 587 routes, anonymous + forged + `alg:none` tokens):
**0 findings** — 1,716 refused (401), 15 public routes on the allowlist returned 200. The signed-in phase (`--auth`) was
not run; it needs test-account credentials.

**Medium**
- Holders of `*_assign_school` can grant themselves review rights (`permissionManagement.controller.js:937-1018`).
- No separation of duties: applicant can review/approve own submission (`review.service.js:206,359`, `grant.service.js:546,717`).
- Email change without re-authentication or confirmation (`auth.service.js:296-306`) → session theft becomes account takeover.
- `/uploads` access is tenant-wide, not ownership-based, for manuscripts and IPR annexures (`fileAccess.service.js:117-121`).
- `GET /research/lookup/:registrationNumber` returns any user's email/phone (`contribution.service.js:1135-1165`).
- Finance routes all 403 (department type `research-patent` never matches, `finance.routes.js:10-16`); once fixed, payout takes the amount from the request body with no status check or transaction.
- Rate limiting and cache are per process (PM2 runs 2 instances, memory cache) — limits multiply, revocations not shared.
- Validation ad hoc: ~25 write-route files without schema validation; 233 `findMany` without `take`.
- Bulk upload (up to 5,000 rows, bcrypt per row) and publication sync run inside the HTTP request; external `fetch` calls have no timeout.
- Scheduled publication sync picks 500 identities with no ordering → some may never sync.
- One audit-log insert per request including GETs; consent gate fails open on error; ~32 handlers return raw `error.message` on 500.

**Low** — login lockout enables account-existence probing/DoS; bulk upload can create tenant admins; public licence-verify can overwrite `pendingHardwareId`; 83 `console.log` in `src`; notification retries without idempotency.

**Verified OK** — JWT (HS256 pinned, revocation, httpOnly/secure cookie), password reset (hashed single-use tokens, no enumeration), superadmin header validation, parameterised raw SQL with tenant filters, tenant-prefixed cache keys, helmet/CORS/body limits, no secrets committed.

## 3. Database

Migrations up to date, no drift (5 migrations). ~40 integrity checks: **0 orphans, 0 duplicates, 0 cross-tenant mismatches** — most issues below are latent and appear with the second tenant or the first user deletion.

- **High** — `IncentivePolicy @@unique([universityId, iprType, isActive])` allows only one *inactive* policy per type; replacing a policy twice fails, and the deactivate/create pair is not transactional (`schema.prisma:1144`, `incentive.policy.controller.js:143-157`).
- **High** — Tenancy migration `20260930150000` adds `university_id NOT NULL` to ~40 tables without backfill and drops 15 legacy tables → cannot be applied to a populated legacy production DB as-is.
- **High** — `audit_log` grew 19,600 rows in ~31 h (READ events logged); 43 % have NULL `university_id` and are never purged; retention is dry-run by default; no `(university_id, created_at)` index.
- **Medium** — nullable `universityId` on tenant tables (`DocumentChange`, `ChangeHistory`, `Notification`, `BugReport`, DPDP consent/requests/nominees/breaches); no composite FKs to stop cross-tenant parent links; ID columns without FKs (`currentReviewerId`, `approvedById`, …); `assignedRoleIds` stored as JSON array; 48 FK columns without an index; no GIN/trigram indexes for the ~20 `contains` searches; 113 never-used indexes; nullable columns in unique constraints (need `NULLS NOT DISTINCT`).
- **Medium** — CI migrates only on `main` (default branch is `fresh-main`), in parallel with deploy, over the pooler host.
- **Low** — free-text statuses where enums exist; 109-column `research_contribution`; inconsistent soft-delete.
- **Already right** — all timestamps `timestamptz`, money is `Decimal`/integer cents, reset tokens hashed, no Aadhaar/PAN columns.

**DPDP gaps at DB level** — no column-level encryption for phone/address/DOB/guardian contacts; erasure misses `ipr_applicant_details`, `research_contribution_applicant_details`, `personal_email`, author phones, bug-report emails, AI chat, audit-log IP/UA and uploaded files; retention skips AI chat, API usage, import runs and NULL-tenant audit rows.
